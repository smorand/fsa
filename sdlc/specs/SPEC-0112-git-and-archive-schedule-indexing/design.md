# SPEC-0112: Git operations and archive extraction schedule indexing, design

> Spec: sdlc/specs/SPEC-0112-git-and-archive-schedule-indexing/spec.md
> Nature: FEAT
> Depth: M
> Security: none
> Designed on: 2026-11-26
> Target tier: 1

## 1. Stack and skills
Existing stack, skill `rust`. No new dependency (S-22).

## 2. Approaches
### Chosen: a log of applied paths on the repository entry, drained by the tool wrappers
`apply_changes_atomically` (the one place git writes the volume) records each path after it really changed it into `GitRepoEntry::applied`. The `tool_*` wrapper of each operation drains the log after the operation returned, whatever the answer, and calls `search::indexer::after_git_changes`, which calls `after_write_reread` and `after_delete`. Pros: exactly the touched paths, partial applies included, no state through 12 inner signatures nor 100 test call sites. Cons: a side channel; two concurrent operations may drain each other's paths, which is harmless (idempotent scheduling, one waiting job per file).
### Rejected: pass `AppState` through every git function
12 signatures and the test helpers change for no behavior gain.
### Rejected: schedule from the tree delta computed by each operation
Misses a partial apply and duplicates the diff in 12 places.
### Rejected: diff the volume before and after
Reads the whole volume.

## 3. Architecture
```
git op -> charge_and_apply -> apply_changes_atomically --record--> entry.applied
tool_X wrapper (follow!) --after the op--> entry.applied.take() -> indexer::after_git_changes -> scheduler
fs.extract_archive --each file written--> collected -> indexer::after_write_reread (also on error)
```

## 4. Data model
None. `GitRepoEntry::applied: std::sync::Mutex<AppliedPaths { written, deleted }>` in memory.

## 5. Contracts and interfaces
`indexer::after_git_changes(state, volume_id, written: &[String], deleted: &[String], client)`. `merge::charge_and_apply` and `apply_changes_atomically` take `entry`'s log. Wrappers generated by `follow_index!` keep their signatures.

## 6. Decisions
- DEC-001 (S-2B) one apply point, one drain helper.
- DEC-002 (S-05) hooks run after the operation returned, never under a lock (FR-NEW-005).
- DEC-003 (S-05) a path both deleted and written in one apply is only written (type change keeps the file).

## 7. Files touched
`git/repo.rs`, `git/merge.rs`, `tools/git.rs`, `tools/archive.rs`, `tools/archive_single.rs`, `search/indexer.rs`, new `tools/git_index_e2e.rs` and `tools/archive_index_e2e.rs`; docs README.md, AGENTS.md, `.agent_docs/search.md`, `.agent_docs/testing.md`.

## 8. Stories
- US-0335 git operations follow the index (S1, S3, F1, F2, F3, X1, X2, X3, X5, X6, X7).
- US-0336 archive extraction follows the index (S2, F2, X4, X5, single files, overwrite).
- US-0337 PostgreSQL, docs and contract.

## 9. Risks
- A drained log read before the apply finishes of another operation: harmless, see 2.
- A hook under a lock would deadlock the scheduler: the drain is in the wrapper, after `on_git_thread` returned.
